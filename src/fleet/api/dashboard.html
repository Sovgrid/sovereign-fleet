Configure fleet dispatch autonomy governance and automated execution gating.
LimitsHow long one agent run may take
How long one agent run (daemon executor or fleet run) may take; then its whole process tree is stopped and the work so far stays on the task's branch. With the grid backend the runner has its own timeout.
Quality gatesWhat has to pass before a task is done
ALWAYS ON
Before a task counts as done: the change stays inside its allowed paths, Python still parses, the repository gate passes (projects.<name>.gate, verify.sh or pytest), the task's own test passes and the files it claimed changed. The gates run in the agent's sandbox without credentials. They cannot be switched off here: a task that skipped them would not be verified.
Keys and sandboxWhere provider keys come from; the kernel sandbox
CREDENTIAL PLUGIN
Lanes draw provider keys from the plugin configured in fleet.toml [plugins]. Off: keys come from each lane's key_file or the daemon's environment.
LANDLOCK + SECCOMP SANDBOX
Agent CLIs write only to their worktree and their own state. Not switchable from the web: only FLEET_SANDBOX=0 in the daemon's environment turns it off.
